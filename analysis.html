三句话版本 · ELEVATOR PITCH

  1. 1
    是什么：本地优先的 Web 工具——把系统截图粘贴进来，AI 视觉模型看懂界面，自动生成结构化操作手册，一键导出政企级 Word（.docx）。
  2. 2
    解决什么：手册编写 80% 是重复劳动（截图、画红框标序号、逐字写说明、整理字段表、调 Word 排版），本工具把其中大部分交给 AI，目标效率提升 70% 以上。
  3. 3
    差异点：AI 不是「看图猜」，而是看你用红框 / ①②③ 序号标注过的截图；用业务术语词典约束 AI 统一用词；产出直接是带自动编号图注（图 X-Y）的标准交付文档。

02

核心工作流

CORE WORKFLOW
1

建立项目与目录树 MANUAL STRUCTURE

创建手册项目，维护左侧多级章节目录树（编号 1 / 1.1 / 2.1 自动计算），配置项目专属业务术语词典。

2

采集截图与视觉标注 CAPTURE & ANNOTATE

Ctrl+V / 拖拽 / 上传批量导入系统截图（>1920px 自动等比压缩）；Canvas 标注器添加红框、①②③序号角标、箭头、马赛克脱敏。

3

AI 多模态解析与生成 VISION LLM

填写一句意图说明，将标注后的截图 + 意图 + 术语词典发给视觉大模型，按严格 JSON Schema 返回：功能概述 / 前置条件 / 与截图一一对应的分步说明 / 页面字段控件表 / 注意事项 FAQ。

4

结构化微调 EDITOR

卡片式编辑器中拖拽排序步骤、就地编辑文本与字段表、针对单步调用 AI 局部润色。

5

标准格式一键导出 EXPORT

导出 .docx（多级标题 + 居中图片 + 自动编号图注「图 X-Y」+ 4 列字段表）或 .zip（Markdown + assets 截图资源包）。

一句话：截图贴进来，标注点两句，AI 写成章，一键变 Word

04

数据契约 · 三个设计亮点

DATA CONTRACT

① 标注坐标归一化

所有标注图形的坐标与尺寸均相对原图宽高存储。截图分辨率再变、窗口再缩放，红框绝不偏移。

x: 0.42, y: 0.18, width: 0.16, height: 0.05

② 每张图存两份 Base64

同时保存原图与合成标注后的图。发给 AI 的是合成图——AI 真的能看见红框和序号；坐标数组保留，可随时二次微调。

rawBase64: 原图 annotatedBase64: 标注合成图 annotations: 坐标数组

③ 章节模型 = 文档结构

章节字段排布与最终 Word 文档一一对应，编辑即所见、所见即导出，杜绝「排版两层皮」。

overview → prerequisites → steps → fields → precautions

亮点与已知边界

STRENGTHS & LIMITS

✓ 技术亮点

  • 数据契约先行：8 个核心接口一次定义，全层复用，零 any
  • 写穿持久化 + 章节自动重编号，删中间章节后续编号自动补位
  • 大图自动压缩（>1920px 等比降采样，PNG 无损保文字清晰）
  • AI 配置与业务数据隔离存储，Key 不随项目数据走
  • 示例数据 Canvas 程序化生成，克隆即可跑，无需准备素材

! 已知边界（主动说明反而加分）

  • 纯本地存储：换浏览器 / 清站点数据会丢，后续加备份导入导出
  • AI Key 用户自理：工具不托管密钥，支持任意 OpenAI 兼容端点
  • 单项目结构，多项目切换是后续增强
  • 标注器 / AI 生成 / 导出引擎仍在建设中（阶段二~四）

常见提问预答

  1. 和直接手写 Word 比强在哪？——截图导入、结构化编辑、编号/图注/表格全自动，AI 承担初稿。
  2. 和 Confluence / 语雀比？——那些是通用文档平台；本工具是「手册生产线」：从截图到成品文档的垂直工作流。
  3. 数据安全？——本地优先，数据不出浏览器；只有点击 AI 生成时，所选截图才发给你自己配置的模型端点。
  4. AI 写错了怎么办？——AI 只出初稿，所有内容结构化可编辑；术语词典 + temperature=0.2 约束严谨性。
  5. 能团队协作吗？——当前单机版，数据模型已按可协作方向设计，后续接云端。
